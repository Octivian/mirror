## 七、某蛋糕品牌A全渠道实收口径（2026-10-11 重写；Mirror 二次强调，最高优先级）

### ★★ 铁律（2026-10 踩过最大的一次坑）

**有赞后台的「营业收入」既不是全渠道，也不是有赞自营——它里面本来就装着外部渠道。**

外部三渠道在有赞后台共出现两处：

| 出现在哪 | 名称 |
|---|---|
| 支付方式明细 | 「抖音支付」（导出名：**抖音券支付**）｜「**美团点评券支付**」（美团团购）｜「**美团**」（美团外卖） |
| 销售渠道构成 | 「**美团外卖渠道**」 |

**正确全渠道 ＝（先在有赞里剔除外部渠道 → 得「有赞自营」）＋（再加三个外部渠道自己后台的数）。**

- **剔除＝白名单**（Mirror 原话）：只算有赞平台自身的支付方式——**微信支付／支付宝／储值余额本金／储值余额赠送金／小红书担保支付／有赞零钱／现金** 等。
- 等价黑名单写法：`有赞营业收入 − 抖音支付 − 美团点评券支付 − 美团`。
- 外部渠道**必须用平台后台数**：不经有赞核销的那部分不在有赞里，有赞侧恒略低。
- **有赞「营业收入」当全渠道用 = 把外部渠道算两遍 + 虚增同比**（26·7 有赞营业收入同比 +135.4%，全渠道只有 +50.8%）。

黑名单公式（台账 3.2 原文，2026-10-02 定）：
```
月实收 = 有赞·营业收入合计 − 抖音券支付 − 美团点评券支付 − 美团
       + 抖音核销金额 + 美团消费金额 + 外卖营业收入
```
| 平台 | sheet | 取哪一列 |
|---|---|---|
| 抖音 | `抖音`（按 [1]「月」，`2026/07`） | [9] **核销金额** |
| 美团 | `美团`（按 [1]「日期」，`202607`） | [32] **消费金额**（≠成交金额、≠用户实付） |
| 外卖 | `外卖`（按 [1]「月份提取」） | [8] **营业收入** |

### ⛔ 数据作业三禁令（2026-10-11 立，最高优先级；详见 `_数据口径与交付规范.md` 第四部分）

起因：某蛋糕品牌A Q3 复盘 08／09 两页把「有赞营业收入」当全渠道实收（7 月同比写成 +135.4%，实为 +50.8%；8 月方向写反），被质疑三轮、前两轮都答「数据是准的」。

1. **只认 L0 原始凭证当基准**（后台截图／客户原始导出列）。我方做的中间表（如 `某蛋糕品牌A_4-9月经营数据统计_v2.xlsx`）是加工品，**会封装错误**，不能当基准。
2. **禁止同级互核、禁止自我循环验证**。PPT ↔ 我做的表 逐格一致，只能证明**转录对**，不能证明**口径对**；同源 ≠ 正确。
3. **落稿前必跑三断言**：① 这格的口径**名字**是什么 ② **自证断言**（单渠道 ≤ 全渠道？分项和 = 合计？）③ **方向断言**（换正确口径，同比方向会不会反过来）。
4. 被问"准不准"时**先反问**：核数字还是核口径？回答必须分「转录／口径／覆盖」三层，**禁止只答转录一致就说"准"**。
5. **核不了的项必须显式申报**，沉默跳过＝默认没问题，是最危险的失败模式。

## 九、复盘口径偏好（Mirror 明确过）

- 数据页**优先用同比**（去年同月、同口径），不用"提案前"这类模糊基线。
- **门店类同比使用前先确认期内形态/面积是否变过**；变过则单列，不混进"经营变差"叙事。
- **日历错位节点**（中秋/春节）按"节点前 N 天＋当天"对齐，并单独考虑两年的**上架日差异**。
- 命题式收束语必须配得上落地措施；**没有落地措施的"下一季要怎样"等于没写**。
- 客户内部管理类问题（如研发责任归属）：**只讲现象和影响，不给落地机制**。

## 十、私域／会员测试读数规则（2026-10-06）

- **分母先换掉**：个微/社群/朋友圈无广播能力，"触达 N 人"≠N 人看到 → 分母必须是实际曝光人数。
- **必须有对照组**（同分层留 10–20% 不发）；没对照只能读"量"，读不出"增量"。
- **券面与门店价格体系对表**：先查该客户各渠道实际折扣，别让券比客人已买到的最低价还贵。
- **钩子选客人本来就会点的品类**（先看品类占比再定钩子）。
- **时点避开大假**，在周一到周四淡日跑。
- **人群优先存量**（有消费记录、未彻底走的人），先分层再触达。
- **储值余额是最短激活路径**，永远排在拉新之前。

## 十一、月度计划编排偏好（2026-09-21 Mirror 微调版教我的）

1. **收口往前压**：节点结束后的事压进"节点后第一个完整周"内收完，不占新月资源。
2. **上架日从节点日倒推**，不是从准备完成日往后排（万圣 10/31 → 10/24 上架，留 7 天窗口）。
3. **月度表只装"本月能做完、能看见结果"的事**；方法论/基建型任务（归因埋点、搜索占位、验收口径、注册入口）放复盘/年度规划。
4. **动作写到"发什么、送几个、什么价"**，一线拿着能直接排队。
5. **人群口径要收紧**（"礼盒购买用户" → "大客户（5 盒以上）"）。
6. **"重复打扰"按人群是否重叠判断**，不按当月批次数。
7. **板块按"谁执行"分**，不按方法论分组（板块名匹配客户组织分工）。
8. **先诊断、先培训，再调配置、再投钱**。
9. **每行备注带可数验收**（3 天清完、送 3 个、报价 100 以下），避免"恶化即调整"。

## 十四、活动连带消费诊断口径（2026-11-10 立，最高优先级）

**★ ROI 闸门**：算净额／每卡净赚／ROI **之前**，必须逐卡跟 Mirror 对清楚权益内容——附赠产品名称、规格尺寸、每卡份数、单份成本（或售价）、是否可折现、有效期。不同卡项附赠不同，**严禁用统一「每份 29 元」估算**（2026-11 某蛋糕品牌A复盘据此写出的「每张净赚 24／112 元、净亏 35 元」已全部作废）。未确认前：净额、每卡净赚、ROI、成本上限、「该不该继续做」定论一律挂起，页面写「待确认」；可先给不依赖成本的确定数。公式：`净额 = 卡收入 +（卡后实收−卡前实收）×毛利率 − 兑换笔数×该卡单份成本`。**毛利率 ≠ 权益成本**。
