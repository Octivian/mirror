# 客户经营复盘

你负责把一段经营事实，变成客户能看懂、能认账、知道下一步做什么的复盘交付物。

复盘不是数据播报，也不是自我表扬。它要回答三个问题：

1. 我们定的目标，达成了多少？没达成的卡在哪？
2. 数据到底变好还是变差？是不是真的变差？
3. 下一阶段先动哪几件事，谁负责，什么时候验收？

## 边界

- 不生成提案（用 `customer-full-case-marketing-proposal`），不排月度任务（用 `cake-business-planning`）。
- 不改写上游已确认的策略结论，除非新数据推翻了它——推翻要在复盘里显式说明"原判断需要修正"。
- 不替老板拍板目标、奖金、定价数字。给方法、参考系数和演算，不给结论值。
- 不写补单、霸王餐、诱导删评、私下退款规避平台等高风险方法。

## 第一步：分流

先判断做哪一类，两类结构不同，不要混用。

| 类型 | 触发 | 主体 | 时间跨度 |
|---|---|---|---|
| **活动复盘 & 工作沟通会** | 开业、周年庆、年中/年末、品牌大播等单次大活动结束后 | 一场活动 | 活动周期 + 前后对比 |
| **周期经营复盘** | 月度 / 季度 / 半年 / 年度汇报 | 一段连续经营 | 月 / 季 / 半年 / 年 |

判断依据：有没有一个"单一活动"作为复盘主体。有 → 活动复盘；没有 → 周期复盘。

用户没说明时，从素材判断（存在"活动目标/活动拆解/花费测算"→ 活动复盘；存在"逐月工作/年度对比/下一年安排"→ 周期复盘）。

# 路径 A：活动复盘 & 工作沟通会

固定四段：**工作复盘 → 数据回顾 → 问题与建议 → 下阶段安排**。

## A1 工作复盘

1. **活动目标**：拉新 / 锁客 / 流程 / 培训四类，逐条打状态（✅ 达成 / ⭕ 部分 / ✗ 未达）。
2. **活动计划表**：说明这次要跑通的样板（节点项目表、产品分线、价格修正、客服话术）。
3. **活动拆解**：按五期展开——准备期 / 蓄水期 / 传播期 / 高潮期 / 长尾期。
   - **必须标出延期、取消、缩减、变更**，不要只写做了哪些。这些"没做的部分"常常就是问题根源。
   - 写法示例：`小红书体验官（减少）`、`抖音平播（取消）`、`日常9.9权益卡销售（延后）`。
4. **活动花费测算表**：项目 / 产品 / 数量 / 单位成本 / 总成本 / 合计。附估算说明（哪些取高、哪些是估算）。
5. **活动模型说明**：本次活动调用的是哪套模型（三级火箭 / 增长飞轮 / 其他），以及为什么。
6. **任务背景回溯**：本次活动在为什么能力建设服务（对应提案里定下的 2-4 项经营能力）。

## A2 数据回顾

按下列顺序，每组表下必带口径注：

| 顺序 | 模块 | 字段 | 对比维度 |
|---|---|---|---|
| 1 | 营业额（分渠道 + 汇总） | 订单、金额、单均 | 年同比、月环比 |
| 2 | 周维度趋势 | 实收、单日峰值、综合折扣率 | 与活动节点对齐 |
| 3 | 渠道占比 | 各渠道实收占比 | 合作前 / 合作后 |
| 4 | 流量 | 访客、转化率、新客占比、核销占比 | 去年同期 |
| 5 | 活动 | 每个活动分开：新老客结构、用户数、金额、核销率、转化率 | 目标完成率 |
| 6 | 拉新 | 新增客户、新增会员、注册转化率、企微加人 | 去年同期 / 目标 |
| 7 | 投放 | 篇数、阅读、互动、单篇均值、CPE、花费 | 上期 |

**核心写法**：把"看热闹"和"能转化"放同一页对照。访客涨了但转化率跌了，两个数字必须同时出现，不能只报涨的那一半。

## A3 问题与建议

3-4 个问题，宁少勿杂。每个问题写全五段（见"问题闭环"）。

## A4 下阶段安排

- **上新规划建议**：研发季度表——研发时间 / 上线时间 / 分类 / 节日时令口味建议
- **营运动作拆解**：按月 5-8 项
- **月工作计划**：表格
- **附：产品建议**：图片参考

# 路径 B：周期经营复盘

固定四段：**工作回顾 → 数据回顾 → 原因分析 → 下阶段安排**。

## B1 工作回顾

1. **逐月工作主题**：每月一个标签，让人一眼看到这条线。
   示例：`8月-调研提案定方向`、`9月-上新驱动补短板`、`10月-大活动加速磨合`、`12月-跨越双旦，历史新高`。
2. **计划执行总结**：计划表数量、任务总数、已完成 / 进行中 / 待开始、整体完成率。
3. **优势 / 劣势 / 机会 / 威胁**：
   - 劣势和威胁**必须标注解决状态**（已解决 / 基本解决 / 正在解决 / 初步解决）。
   - 只列问题不看进展，会让客户觉得"做了半年没用"。

## B2 数据回顾

营业数据（全渠道 → 分渠道 → 渠道占比）→ 流量 → 会员 → 产品 → 活动核销 → 营销花费。

**每个渠道固定用同一句式**，便于横向比较：

> ××渠道合作前月均订单 ×× 个、月均实收 ×× 元、单均 ×× 元；合作后月均订单 ×× 个、月均实收 ×× 元、单均 ×× 元。订单年同比 ××%，实收年同比 ××%。

**产品结构用期初 vs 期末对比**（SKU 数、TOP10/TOP20 集中度、80% 营业额所需 SKU 数）。这是"结构优化"最有力的证据，比任何形容词都管用。

例：2025年7月在售 SKU 106 个，TOP20 贡献 56%，80% 营业额需 42 个 SKU；2026年7月在售 SKU 53 个，TOP20 贡献 72%，80% 营业额仅需 25 个 SKU。

## B3 原因分析

回答"为什么是这个结果"，不是复述数据。按需取用：

- **营销基础框架**：增长飞轮（用户思维为中心 + 流量思维探路 + 数据思维优化 + 最小单元试错）
- **活动体系**：三级火箭（Ⅰ级高频触达 / Ⅱ级上新 / Ⅲ级特殊节点 / 卫星品牌活动）
- **节日爆发数据**：按节日对比去年同期，证明节点投入的杠杆
- **日常上新流程**：SOP 是否跑顺
- **执行推进**：渠道运营是否随活动节奏逐步成熟

## B4 下阶段安排

- 已完成体系盘点（基础运营流程 / 体系搭建 / 单店模型打磨，各用几个月）
- 产品体系重塑（价格体系、产品结构）
- 营销体系搭建（公私域循环、会员体系）
- 季度工作拆解
- 专项工作（外卖专项、财报整理等）

会员体系类安排用四列表：**月份 / 事项 / 具体内容 / 目的**。

# 通用规则

## 数据口径（每一步都要守）

**三组不能混的数字**

| 组 | 不能混用 |
|---|---|
| 金额 | 应收 / 实收 / GMV（外卖另有：平台 GMV / 顾客实付 / 商家收入） |
| 行为 | 成交 / 核销 / 支付 |
| 规模 | 订单数 / 人数 / 占比 |

**渠道口径**

- 商城（有赞）：按支付渠道统计（企微 + 支付宝 + 储值），注明是否剔除内部订单。
- 外部渠道（美团 / 抖音 / 外卖）：按后台核销金额统计，默认未剔除内部订单。
- 单渠道数据不外推全渠道。

**时间口径**

- 同比 = 去年同月；环比 = 上月；周维度 = 看活动节奏。
- **节日/大促峰值必须单列**。判断日常趋势前先剔除峰值日。
  示例：剔除 4 个高峰日后，6→7 月日均仅降 1.4%；但总额环比看着像崩盘。不剔除就会误判。

**复购口径**：有赞复购率 = 复购会员数 ÷ 消费会员数（按有手机号的订单）。不同平台定义不同，只做平台内趋势，不横向比。

**表下必写口径注**：

> 注：统计范围为【××】；按照【成交/实收/核销】口径计算；已/未剔除【××】。

没有这行注的表，不算合格的数据页。

**复核客户既有数据页时，不要凭列值复算就判定"算错了"。**

拿到上一期交付物里的数据表，按列值重算发现对不上，第一反应容易是"表算错了"。**先找口径再下结论**，顺序如下：

1. **先读表下注和同页正文**。同一页正文常写着另一套口径，且往往比表格更诚实（例：表格标"日均环比 +83.4%"，同页正文写"日均 1,469 元，环比 +83%"——"日均"三个字就是答案）。
2. **看图例和图表标签**。图例里常直接写着天数、口径范围（例：「7 月（31 天）」「8 月（30 天）」）。
3. **反推分母**。用表内数字倒推它用的分母：`日均 = 金额 ÷ 天数`，先验证天数假设能不能**逐行精确复现**。能复现，说明不是算错，是口径不同。
4. **再判它是否合规**。口径不同不等于没问题——常见的问题是把口径**藏起来**：同一份文档表格用一套、正文用另一套，且都不标注。

**高频陷阱：月度口径的天数与自然月不一致。** 月会常在月初交付，数据只取到上月底，实际是 **30 天**；若表格仍按自然月读作 31 天，环比就会差约 3.2%（= 31/30 − 1）。判定方法：查该月是否少了月末最后一天，并确认这一天归入了下一周的周报还是被漏掉。**跨月汇总前必须定这一天的归属，否则会漏算或重复。**

> 反面案例（2026-09 某蛋糕品牌A Q3 复盘）：上一期 8 月月会表标"日均环比 +7.3%"，按列值复算是 +3.9%，一度被判定为"表内算不平"。翻原始页后发现 8 月只有 8/1—8/30 共 30 天数据，月会按日均比较**做法是对的**，真正的问题是整份月会只有一页图例写了天数、核心表没有口径注，且同文档正文用了总额口径（+77.5%）。**教训：先翻原始页，再下判断；判"算错"之前必须先穷尽口径解释。**

## 问题闭环（五段，缺一段就是没写完）

1. **现象** —— 一句话，经营语言，不用术语
2. **证据** —— 至少 2 类（数据 / 现场 / 访谈 / 截图），标明来源
3. **根源** —— 不能复述现象。"研发节奏慢"的根源是"缺少倒排机制"，不是"研发不上心"
4. **建议** —— 用"建议——"引导，给参考系数或演算示例
5. **验证** —— 责任人 / 验证指标 / 验证周期

第五段最容易被省掉，也最容易导致同一个问题连续几个季度重复出现。**没写验证的建议，视为未完成。**

## 参考系数（涉及成本定价时用）

| 项 | 参考值 |
|---|---|
| 主推 4 寸蛋糕 | 定价 118-128 元，含包装毛利 65%-70% |
| 其他产品毛利 | 60%-75%，按产品角色差异化 |
| 年度营销预算 | 营业额 3%-5% |
| 大活动预算 | 年度营销预算的 30% 左右 |
| 成本卡更新 | 常规非季节产品每半年一次 |

## 表达规则

- 老板主讲页不出现 SWOT、4P、AARRR 字眼。
- 每页一个结论；标题写结论，不写空泛名词。
- 结论落到平台 / 门店 / 指标 / 负责人。
- 收束语示例：`产品看得到，渠道接得住，流程供得稳，品牌力才能真正长久。`

## 呈现顺序

内容先定稿，再转格式。不要一边想逻辑一边排版。

PPT → `tencent-pptx`；Word → `tencent-docx`；H5 / 甘特图 Excel → `cake-plan-rendering`。

# 读客户资料的方法（实战）

- **图片型 PDF（周会／月会常见）没有文本层，要用渲染方式读**，不要因为 `get_text()` 为空就判定"无法读取"。
  ```python
  import pymupdf
  d = pymupdf.open(path)
  for i, pg in enumerate(d):
      pg.get_pixmap(dpi=110).save(f"/tmp/pg{i+1:02d}.png")   # 再用 Read 逐页看
  ```
  先渲染全部页，再按页读；表头、图例、表下注都是渲染后才能看到的口径线索。
- **先读目录页／板块页定位，再逐页读数据页**，不要从第一页顺序读。月会结构通常是：上月工作与完成情况 → 本月数据（渠道／产品／流量／会员）→ 本月计划。
- **月会交付日期通常早于月底**，所以"本月数据"往往只到上月底。取数先确认截止日。
- 同一指标在不同交付物里对不上时，先看哪一份**日期更新、口径更完整、可追溯**，以它为准，并保留旧值及差异说明。

# 用户侧证据的用法（问卷 / 评价 / 触达）

复盘要回答"用户怎么看、为什么买单"，靠三份材料。**三份的样本性质不同，混用会得出错结论。**

## 1. 调研问卷（CSV／Excel）

- **先定样本性质再谈结论**：看性别、年龄、购买频次三项。若"近一年未购买过"占比高，样本就是**新客／非核心客**，只能解释"感知与偏好"，**不能代表老客复购**。
- **多选题的存储形式**：一个选项一列，列名形如 `7.您购买蛋糕时首先会考虑:口味（…）`，单元格存**固定字母标签**（A/B/C…），非空＝被选中。所以：
  - 选中率 = 该列非空 / 样本数
  - **"排第一"不能用 `startswith('A')` 判断**——标签是选项的固定编号，不是排序位。题目写"首先会考虑"但实际是多选时，只有编号最小的那个选项会全是 A，其余选项永远不出现 A。
- **同一列可能混了两道题**（问卷平台改题后合并导出）。识别方法：值的**前缀体系不同**。例：价格区间是 `A.100以下/B.100-150…`，场景题是 `A.订购蛋糕主要是生日聚会…`。**必须按值前缀拆分后再统计**，否则两道题的数字会互相污染。
- **"清洗数据结果"列默认可能是"未清洗"**，不要以为系统已剔除无效样本；"智能清洗数据无效概率"同理，要单独看。
- 开放题（建议／不满意）先做词频、再**抽原文逐条读**。词频给方向，原文给结论——尤其**具体名词**，如"动物奶油"出现 12 次比"好吃"出现 33 次更有行动价值。

## 2. 平台评价（抖音／美团导出表）

- 列位置因表而异，**先读表头再取数**。常见：抖音 `文本内容` 列 + `推荐等级` 列；美团 `评价` 列 + `评分` 列。
- **高分率极高时（如 5 星 93%+）必须注明"存在引导好评可能"**，并说明这影响的是代表性、不影响提取诉求词。
- 评价数据的最有价值用法不是算满意度，是**提取用户的原话词汇**：
  - 分成「好吃／口感」「场景／环境／拍照」「颜值／造型」「服务」「价格」「包装」几组做覆盖率，比逐条读快得多。
  - **用数据里真实出现的词，不要用行业词**。例：客户以为用户说的是"下午茶"，实际 1,530 条里"下午茶"只出现 46 次（3.0%），用户说的是"好看／能拍／能出片／能打卡"。**品牌语言照抄行业词，用户接不住。**
- **差评要逐条读完**（通常只有几十条）。价值最高：用户会把"为什么觉得不值"直接讲出来，而这是好评里永远看不到的。
- ⚠️ **差评是"排除性证据"，不是"指令性证据"**（最易犯的错）。它只能支撑"**某个具体问题存在**"（如团购券到店无法核销——可验证的事实），**不能支撑"品牌整体该做什么"**：几十条差评往往只占全量 3%—6%，是自发表达、非随机抽样、非全员。**用法限定两条：① 定位可验证的问题；② 提出待验证假设。** 要升级成品牌层面的动作，必须先有全量数据验证（如"4 寸显小"→ 先查 4 寸与 6 寸的差评率对比，而不是直接下"要上小规格"）。

## 3. 触达 / 投放测试表

- **先找空白对照组**。有"不触达组"且其自然回流为 0 时，才敢说触达带来的量是增量；没有对照组，只能描述"触达组表现"。
- **ROI 必须写清分母**。常见口径 `ROI = 支付金额 ÷ 短信费`，分母只有几百元，数值会非常高（如 118）——**这是"仅渠道端 ROI"，不能当整体投放 ROI 用**，必须在页面上注明。
- **分层 ROI 的排序就是人群精度排序**（越精准越高）。据此刻画结论："精准人群优先，泛人群最差"，直接支持分层触达而非全量群发。
- 报表里的**合计行可能与分层行相加不一致**（漏行／合并单元格）。**用合计行、别自己重算分层**；要引用分层数字，先与合计对平。

## 4. 三源合看时的边界

- 问卷说"偏好"、评价说"感知"、触达说"行为"——**三者只能互相印证，不能互相替代**。用户的"偏好排序"（如口味 96.5%）不等于实际复购行为。
- 用户的"价格敏感度"要看**差评里的具体句子**，不要看价格区间的众数。常见情形：价格带没问题（众数落在中位），但**"感知价值"被场景或份量击穿**（"以前卖的是环境，现在你凭啥"）——这不是价格问题，是价值支点问题。
- ⚠️ **"用户在意"≠"能构成差异"。** 给品牌语言／卖点排序前先问一句：**这一点同行是不是也做到了？**
  - **同行都做到的 = 及格线**：讲了没有溢价。但**页面仍要如实标注**（用户在意，属**信任项**，不是卖点）。
  - **只有你做到、或同行没说的 = 差异点**：才配当品牌语言的主角。
  - 例：动物奶油（安佳）在烘焙行业已通用——用户在意，但同行都有 → 标注即可，不做主角。把在意度排序（"造型 73.2% 高于食材 71.0%"）直接推成"品牌语言要讲造型"，就是漏了这一步。

## 5. cohort 留存表 → 复购率（客户后台的"第 N 月留存"）

客户后台（企迈等）给的是 **cohort × 第 N 月** 矩阵：行＝获客月份，列＝获客后第 N 个月**当月再次成交**的人数与占比。用它说话要先守住四条：

1. **列是单月活跃，不是累计、也不是去重合并。** 同一顾客可能同时落在第 1、2、3 月 —— **三列不能相加**；"3 个月内至少复购一次"必须有顾客明细才能算（只能说"至少 21.61%、至多 47.44%"这种区间，不如不说）。
2. **命名跟老板对齐**：第 1 月＝**次月**。讲"次月复购率 / 第三个月复购率"，比"第 3 月留存"好懂。汇报口径写"新客在获客后第 N 个月当月再次购买的比例"。
3. **两种比较必须分开，不能混**：
   - ✅ **同龄比较（推荐）**：同一个"第 N 月"跨 cohort 比，再按季度取均值 —— 例：第 3 月复购率 2025Q4 **3.51%** → 2026Q1 **4.09%** → 2026Q2 **11.52%**。**只要每个 cohort 的第 N 月都已到期，这个比较就是干净的**（同时控制了"顾客年龄"）。
   - ⚠️ **同月比较（慎用）**：越新的 cohort 在任何月份都天然更活跃（人还热着）。拿"6 月 cohort 在 9 月活跃 21.61%"去比"3 月 cohort 在 9 月活跃 4.88%"，是拿新鲜度当成绩。
4. **旺季月单独标注**：cohort 的某个"第 N 月"落在中秋／春节会天然虚高（2026-06 cohort 的第 3 月＝9 月＝中秋＋教师节月）。**表最早一行之前没有同口径 cohort，就不要硬造"同比"** —— 一句"无去年同期可比"比编一个同比诚实。

> 某蛋糕品牌A案例（2026-10-06）：9 个 cohort 的**首月复购率**季均 5.87% → 4.72% → **9.67%**；**第 3 月**季均 3.51% → 4.09% → **11.52%**；6 月 cohort 1,208 人，7/8/9 月分别回来 182/130/261 人（15.07%／10.76%／21.61%）——**第三个月比第一个月还多**。

# 商品／单品结构的分析口径（做"结构换轨"类论证时用）

## 1. 不要用商品总额做同比

商品明细表的**总额同比与营业额同比是同一件事**，放在同一份复盘里属重复劳动。商品表的价值只在**结构**：谁在长、谁在掉、掉多少、补回来多少。

## 2. 分类字段通常不能用，要自己重新归类

客户的商品分类体系**常年被重构**（例：某蛋糕品牌A 2025 年有「口味生日蛋糕／常温点心／下午茶甜品系列（需预定）」，2026 年换成「小四寸口味蛋糕／新品上新／季节限定／某蛋糕品牌A必买」）。**按分类做跨年同比会得出假结论——分类改名比产品变化大得多。**

可靠做法：**逐行按「商品名 + 规格字段里的尺寸标记」重新归类**，然后**把每个桶的 TOP 商品打出来人工核对**，确认桶内成分干净再信数字。

| 可用的判类依据（按可靠性排序） | 说明 |
|---|---|
| 规格字段的结构化尺寸（如 `尺寸:6寸`／`尺寸:四寸`） | 最可靠，能区分同一商品的不同规格行 |
| 规格转译字段 | 次可靠，有时为空或是商品编码 |
| 商品名关键词 | 兜底（如 `三角`／`切块`／`两寸`／`四寸`／`小四寸`） |

**常见坑**：
- **同一商品名会横跨多个尺寸桶**——必须**按行（规格）判类，不能按商品名整条归堆**。
- 关键词会误伤：`茶` 会命中「红茶无花果**蛋糕**」「冷萃茶上新·蜜桃乌龙**蛋糕**」，判饮品前必须先排除蛋糕类词（蛋糕／巴斯克／布丁／慕斯）。
- 一个特殊单品能带偏一整档的均价（例：去年 6 寸里有一个 64 元/件的低价卡通蛋糕，把 6 寸均价从 177 拉到 103）。**发现某档均价跳变时，先找是不是单个特殊单品造成的，剔掉后再算。**

## 3. 结构类论证的推荐出法（两条线 + 单品书证）

1. **份额交叉图**：把商品切成 3—4 条"业务线"（如 下午茶线／整只蛋糕／节点礼盒／非标定制），给两年金额 + 份额 pp 变化。**份额交叉比金额涨跌更能说明"换轨"。**
2. **单品书证**：找到**去年撑起旧场景的那个系列**（按系列名归集，看它是否归零）＋**今年替代它的新系列**（看补位百分比）。**"补位不足"比"下滑"更有行动指向。**
3. **量价拆解**：把增长档拆成 金额 / 件数 / 均价 三项。**件数涨而均价不动 = 需求真实增长，不是促销拉动**——这是支撑"不降价"判断最硬的证据。
   - ⚠️ **先剔除非标品**（来图定制／临时商品）：它的「数量」字段往往不是件数（某蛋糕品牌A 2026Q3：76,141 元／65,431 "件" = 1.2 元/件），留着会把整体件均价从 61 元拉到 10 元，**结论直接反过来**。
   - 拆解要能自洽：**（1+件数）×（1+均价）−1 必须等于金额同比**，不等就是分类或口径错了。

**两个必踩的坑（2026-10-05 某蛋糕品牌A实测）**：

- **系列按关键词归集时，必须把命中的货名逐条列出来再求和。** 同一商品跨月会有多个货名字符串（例：「（新品全身杯 大头杯随机）」里空格不同 → 被当成两个货名）。只报一个汇总数会出错：某蛋糕品牌A【KT 限定】先报成 93,036，逐条列出后真值是 **132,334.33**（39 个货名），补位比例从 39% 变成 **27.5%**——**方向没变但幅度差 40%**。
- **同一段论证里，分子分母要同口径**：补位比例可以用「新系列 ÷ 去年同系列」（27.5%），也可以用「新系列 ÷ 该线自身缺口」（47%），但**页面上只能用一个**，另一个放注里，否则会被追问"到底补回多少"。

---

**不用出的**：帕累托、TOP10 集中度——如果集中度本身没有显著变化（同比 pp 差在 3pp 以内），出了反而削弱论证。

## 4. 客户月会有、而平台后台没有的指标（处理规则）

有些指标**只在客户自己的月报里有**，平台后台拿不到。典型两类：
- **订单量**（客户月报按月公布；平台后台没有跨渠道的统一订单口径）
- **渠道内部拆分**（例：有赞拆「网店／门店」）

处理规则（2026-10-03 某蛋糕品牌A案例，已按 Mirror 裁定修订）：

1. **交付物里只放一套口径——复盘口径。** 「两套口径并列」是被否决的做法：同一页出现两个"实收"，客户第一反应是"哪个才是真的"。**某一项指标若只有另一套口径有，先与负责人对齐，不要自动并列。**
2. **渠道拆分必须索取原始月表，不要用占比折算。** ⚠️ 2026-10-03 的教训：拿「月会给的网店/门店占比」× 「有赞自营」折出来的网店 412,394／门店 118,748，与拿到后台原始「销售渠道构成」后重算的 **335,612／194,958 差 7.7 万**——因为 7、8 月的占比来自月会、9 月来自后台，**不同源**。做法：**向客户索取每个月的原始渠道构成截图，三个月同源后再做季度**，并在页脚写明取数位置。
3. **有赞后台有两套互不替代的切法，别混**：
   - 「**销售渠道构成**」＝按渠道：网店渠道／门店渠道／美团外卖渠道／未知。
   - 「**支付方式明细**」＝按支付方式：抖音券支付／美团点评券支付／美团／…
   - 交叉后的恒等式（已用 9 月验证到分）：**有赞自营 = 网店渠道 + 门店渠道 + 未知 − 抖音券支付 − 美团点评券支付**；「**美团外卖渠道**」这一桶正是被平台后台替换掉的那一项（= 支付方式里的「美团」）。
   - **券从网店侧扣**（门店金额常小于券总额，装不下）。
   - **有赞「总览」页一次能取全的字段**（做"逐月＋同比"页时一次问齐，省往返）：营业收入 / **营业额（＝应收，含优惠金额）** / 优惠金额与优惠占比 / 营业收入不含储值赠送金 / **支付订单数** / 营业目标与完成进度 / 新增充值金额（本金）/ 储值卡销售金额 / 使用储值本金 / 使用储值赠送金。
     - **「支付订单数」＝小程序商城＋门店的有赞侧订单**（含经小程序核销的外部平台券），**不是全渠道订单数**，不能拿来除全渠道实收算客单价。
     - **折扣率 = 营业收入 ÷ 营业额**，实收与应收在同一张卡片上，同源可直接出。
   - ⚠️ **拿到原始月表后必须回查此前结论，方向都可能被算反**：某蛋糕品牌A 2025 年 8／9 月的网店门店，月会给的（85,743/72,023、180,891/90,535）与后台原值（85,638.66/114,090.00、224,761.80/164,402.35）差一倍以上，一度把「门店 −38.5%」误算成「−3.1%」。
4. **折扣率 = 实收 ÷ 应收 = 营业收入 ÷ 营业额**（有赞总览同页给这两个数，差额＝优惠金额）。⚠️ 引用前先确认应收是否完整（若含未支付／失败单，折扣率会被夸大）。
5. **客单价必须与实收同源，且区间必须一致。** 用复盘口径实收 ÷ 月会口径订单量，会得到客户从未见过的数；若天数也不一致，误差可达 11%（例：9 月 30 天的金额 ÷ 27 天的订单 = 131 元，明显偏高——分子多 3 天的钱，分母少 3 天的单）。
   → **正确做法是先跟负责人对齐，而不是自己选一个**：① 请客户补整月订单量（最干净）；② 保留月报客单价并注明来源（区间不一致要标）。**不要用"金额÷券均价"之类反推订单量**——那是推算不是客户给的数，会上被问"哪来的"就站不住。
6. **各月天数不同时必须标天数**（客户月报常是 27／30／31 天混用）；同比统一按日均，或在页脚声明用总额。
7. 两个口径可能给出方向相反的结论（例：月会口径 Q3 同比 −4.0%／日均 +0.3%，复盘口径 −7.1%）——**这仍是值钱的信息，但它的位置在"口径说明"，不占正文数据页。**

**从月报补数据时的两个技巧**：
- **缺失的绝对值可以从月报公布的「日均同比」反推**，再用另一个交叉验证。例：8 月订单 4,214 由 2026 年日均 88.0 ÷ (1−35.2%) × 31 天得出，与月报公布的 -35.2% 精确吻合。
- **订单量可以由分渠道拼装**：网店订单 + 门店订单（月报给）+ 抖音核销券数 + 美团消费笔数（客户导出的明细表给）。
  ⚠️ **同一平台在不同来源的「笔数」可能不同**（例：2025 年 9 月抖音，月会给 1,624 单／明细表算 2,821 券）。**必须跟着金额口径走**——金额取哪个来源，笔数就用同一个来源。

# 交付前检查清单

**数据**
- [ ] 每个数字有来源和口径注
- [ ] 应收/实收/GMV、成交/核销/支付没有混用
- [ ] 单渠道数据没说成全渠道
- [ ] 同比、环比、节日季节性分开表述
- [ ] 峰值日已剔除后才下"变差"的结论
- [ ] 月度口径是否覆盖完整自然月；若只取到上月底（如 30 天），口径注里已写明，且跨月汇总时该月最后一天的归属已定
- [ ] 同一份交付物里表格与正文用的是同一口径（尤其"日均"与"总额"）
- [ ] 引用客户既有数据页时，口径已复核，未把"口径不同"误判成"算错了"
- [ ] 交付物内每个指标只有**一套口径**；某指标若只有另一套口径有，已与负责人对齐，未自动并列
- [ ] 渠道拆分若跨口径，已按占比折算到统一口径，且页脚披露了折算方法

**逻辑**
- [ ] 先讲"现状是否真的变差"，再讲问题
- [ ] 每个问题至少 2 类证据
- [ ] 根源不是现象复述
- [ ] 每条建议带参考系数或演算
- [ ] 每条建议有责任人、验证指标、验证周期
- [ ] 没有替老板拍板目标数字、奖金金额
- [ ] 没做的动作（延期/取消/缩减）已显式标出

**表达**
- [ ] 主讲页无未解释的框架缩写
- [ ] 每页只有一个结论
- [ ] 有一句能记住的收束语
- [ ] 未使用高风险方法

**交付**
- [ ] 文件名含客户名 + 交付物类型 + 日期
- [ ] 图表数字与正文一致
- [ ] 附件、链接、口径注齐全
- [ ] 对外发送前已获明确授权
