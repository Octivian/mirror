# 用户需求洞察报告技能

把两类非结构化用户声音——主动问卷、被动评价——转成客户能认账的经营结论和报告。

权威底稿：`references/workflow.md`，为资料库文档《用户需求洞察报告·可复用工作流》全文（Miro 基于 2026-08「某蛋糕品牌A」首轮实操逆向整理，2026-10-16 建档），仅做组件标签 → Markdown 的版式转换，**结论、数字、口径、章节顺序未改动**。本文件只给流程、纪律与索引；两者冲突时以底稿为准，不得用本文件覆盖底稿里的结论。

## 一、三条铁律（每次执行都守）

1. **不臆造。** 每个数字必须能追到源文件与口径；没拿到的数据留空或标「待补」，不编、不推算、不拿上一期数字顶替。底稿第九章列了四条**已知口径问题（待复核）**——「317 份问卷」（历史成品实为 228 份 / 去重后 86 份）、「1,500 条评价」（脚本统计 1,560 条）、样本收集期「6–9 月」与「5–8 月」冲突、某连锁蛋糕B与某蛋糕品牌A评价数据混放——引用前必须核对，**不得当已核实事实使用**；发现结果与源文件不一致时立即同步，不自行抹平。
2. **先列资料清单、确认客户，再动手。** 按底稿第二章列出所需输入，确认客户身份与对应成品形态；**源文件字段与列名先核对再统计**，禁止凭经验套列名（评价表列位置因表而异，问卷多选是「一个选项一列」）。缺文件就明说缺什么，不用相似文件凑数；任何数据改动先确认再执行。
3. **人工环节不得伪装成算法输出。** 差评 7 类归因、竞品清单与「用户心智」词、报告核心结论 3–5 条，必须逐条读原文人工判断；**换客户/换周期一律重做**。报告里写明哪些是脚本算的、哪些是人工标的。

## 二、何时用 / 何时不用

| 场景 | 走哪 |
|---|---|
| 客户要独立的用户画像、选购偏好、竞品感知、口碑诊断、需求缺口报告 | **本技能** |
| 复盘 PPT 里要几页「用户需求洞察」 | 本技能产出结论 → 交 `cake-client-review` / `cake-ppt-layout` |
| 只是复盘里引用问卷/评价证据，不出独立报告 | `cake-client-review`（其「用户侧证据的用法」章） |
| 周报 / 月报 / 经营数据播报、已定稿内容只做排版 | 对应周月报流程 / `cake-ppt-layout`，不用本技能 |

## 三、开工动作（顺序不跳）

1. **定客户 + 定形态**：按底稿第一章三选一——问卷单体报告（HTML，8 章 + 12 图）/ 策略型诊断（Word，4 节 ≤8 页）/ 诊断型报告（Word，6 页）——确认页数或章节目标。
2. **列清单**：照底稿第二章逐项确认输入到位；评价侧先探查 sheet 名 / shape / 列名 / 前 3 行，问卷侧先读表头与字段构成。
3. **定时间窗口并写进封面 meta**。某蛋糕品牌A取 2025-01-01 起（长期品牌叙事）、某连锁蛋糕B取近 3 个月——换客户重新定，不沿用。
4. **声明样本性质**：问卷随什么活动发放、是否偏新客/达人/打卡人群；评价高分率是否异常（存在引导好评可能）。写进口径卡，不藏在附录。
5. **两路并行跑**（底稿第三、四章），**合并**按第五章 12 个维度表求交集，落成「机会点 / 差异化落点 / P0–P2 行动表」。
6. **出稿**按第六章骨架；**交付前逐条过第七章 18 个坑 + 第八章换客户必改项**。

## 四、两路执行流程（速查）

**问卷路（5 步）**：清洗探针（只打印不落盘）→ 去重裁定（先逐字段比对差异，再按 `开始答题时间` 升序保留最早一条，避免误杀共用手机号的家人）→ 统计（单选归一 / 多选计数 / 7 组交叉 → `stats.json`）→ 开放题关键词词典打标（→ `text_analysis.json`）→ 12 张图 → 单文件 HTML（base64 内嵌图表）。

**评价路**：探查 → 字段归一（抖音「推荐等级」是「5星」文本，需正则取值）→ 导出全量 CSV → 按时间导出全部原文 → **人工逐条归因（7 类框架）** → 指标与 4 图 → 品牌侧图 → Word 报告 → 页数校准。

**合并**：口碑健康度 + 短板聚类（评价路）× 画像 + 决策因素 + 竞品 + 需求缺口（问卷路）→ 差异化落点与行动表。

> **脚本说明**：底稿中的 `step1_clean.py` … `build_*_report.py`、`_helpers.py` 是 Windows 实操记录（`D:\工作\...`），**未随本技能附带，当前环境也不存在**。复用时按上述流程重建脚本，不要假装可以直接调用。所有硬编码 N、分组样本量、题号列名、选项字典、Q10/Q12 关键词词典、时间窗口、品牌色必须按新客户重填——底稿第八章 B 节逐文件列了要改的项。

## 五、口径纪律（最容易翻车的）

- **负面率 ≠ 问题率**：前者 = 星级 ≤3 条数 / 当期评价总数；后者 = 正文提及具体不足的条数 / 当月两平台评价合计（含好评中的瑕疵）。不可混用，不可并列成同一个数。
- **多选占比分母 = 总样本 N**（不是选择人数，占比之和可 >100%）；空值判定只能用 `pd.isna()`，不能用 `str().strip() != ""`。
- **交叉分析用组内分母**，避免总体掩盖差异。
- **平台档位不同**：美团中评 3.5 星、抖音中评 4 星，抖音无 4.5 星档；评分分布对比必须标注。
- **小样本只作方向性提示**（如单月 16 条评价），不下「新趋势」判断。
- **口径冲突必须双计并注明**（某蛋糕品牌A价格意愿一列混了 103 人答价格档位、123 人答消费心态）。
- **「用户在意」≠「能构成差异」**：同行都做到的属及格线（信任项，如实标注但不做主角）；只有自己做到或同行没说的才配当品牌语言主角。
- **差评是排除性证据，不是指令性证据**：只能定位可验证的具体问题或提出待验证假设，不能直接外推成品牌整体策略；要升级必须先有全量数据验证。
- **同一份报告不混用两套开放题归类结果**（关键词词典 / 人工逐条归类，二选一）。
- 每个数据表、图下方写口径注：统计范围、金额或行为口径、是否剔除、样本量、时间窗口。

## 六、表达与交付

- 结论写经营语言，不写框架缩写；核心结论 3–5 条由人工把指标「翻译」成经营判断。
- 引用用户原话用数据里真实出现的词，不套行业词；典型原声需可追溯。
- Word 版式可复用 `_helpers.py` 的样式规范（红/绿高亮 `⟪…⟫` / `⟦…⟧` 由 `rich_para` 解析），换客户一般只改品牌色常量与页眉页脚品牌名。
- 对外发送前必须获得明确授权；文件名含客户名 + 报告类型 + 日期。

**交付前检查**

- [ ] 每个数字有来源与口径注；第九章四条待复核数字未被当成事实
- [ ] 负面率 / 问题率、应收 / 实收、订单 / 人数未混用
- [ ] 样本性质、时间窗口、评价高分率异常已写进口径卡
- [ ] 差评分类、竞品心智词、核心结论为人工产出且可追溯
- [ ] 底稿第八章「必须修改的参数」逐项过完，无遗留硬编码 N 与旧客户文案
- [ ] 结论未越界：差评未外推成品牌策略，同行通用项未被当成差异点
- [ ] 成品形态与客户诉求一致，页数 / 章节达标
